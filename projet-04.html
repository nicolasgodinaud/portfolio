PROJET 04

Analyse de sentiments de tweets

NLP · Deep Learning · MLOps · Déploiement continu sur Azure

NLP LSTM DistilBERT MLFlow Azure MLOps CI/CD

Contexte & problématique

Air Paradis, compagnie aérienne confrontée à des bad buzz récurrents sur les réseaux sociaux, mandate le cabinet MIC pour développer un prototype d'IA capable de prédire automatiquement le sentiment associé à un tweet (positif ou négatif). L'objectif est de détecter en temps réel les signaux négatifs afin de réagir rapidement avant qu'une crise ne s'amplifie.


Le dataset utilisé est Sentiment140, un jeu de données open source de 1,6 million de tweets annotés binairement (sentiment négatif ou positif). Trois approches de modélisation ont été comparées, de la plus simple à la plus avancée, avec une démarche MLOps complète intégrant tracking des expérimentations, versioning, déploiement continu et monitoring en production.

Démarche

  • Prétraitement des tweets : nettoyage, tokenisation, encodage
  • Entraînement d'un modèle baseline (régression logistique) pour référence
  • Entraînement de modèles avancés : LSTM + Word2Vec, LSTM + GloVe, CNN + Word2Vec
  • Fine-tuning de DistilBERT pour évaluer l'apport des Transformers
  • Tracking de toutes les expérimentations avec MLFlow (métriques, artefacts, modèles)
  • Déploiement de l'API Flask sur Azure Web App via pipeline CI/CD (GitHub Actions)
  • Monitoring en production avec Azure Application Insights (traces, alertes email)
  • Développement d'une interface de test Streamlit permettant de soumettre un tweet et de valider ou corriger la prédiction

Le modèle LSTM + Word2Vec a été retenu pour le déploiement : il offre le meilleur compromis entre performance (AUC 0.889) et coût computationnel. DistilBERT obtient une accuracy légèrement supérieure (+0.9%) mais au prix d'un temps d'entraînement et d'inférence bien plus élevé, peu adapté à un déploiement embarqué sur une solution cloud gratuite. La régression logistique sert de baseline solide, avec une accuracy de 78.9% obtenue en quelques secondes d'entraînement.

Pipeline de modélisation

Sentiment140 (1.6M tweets) → Nettoyage & tokenisation → Word embeddings → Entraînement LSTM → MLFlow tracking → API Flask → Azure Web App

Démarche MLOps

MLFlow — Tracking & stockage
Toutes les expérimentations sont enregistrées dans MLFlow : métriques (accuracy, AUC), hyperparamètres, artefacts (modèles, tokenizers). Permet de comparer visuellement les runs et de centraliser le stockage des modèles.
GitHub Actions — CI/CD
Un pipeline de déploiement continu est mis en place via GitHub Actions : à chaque push sur la branche principale, les tests unitaires sont exécutés automatiquement, puis l'API est redéployée sur Azure Web App si les tests passent.
Azure Application Insights — Monitoring
Chaque prédiction et chaque retour utilisateur sont loggés vers Azure Application Insights. Des alertes email automatiques sont déclenchées en cas de volume anormal de prédictions jugées incorrectes par les utilisateurs.
API Flask — /predict & /feedback
L'API expose deux endpoints : /predict qui reçoit un tweet et retourne le sentiment prédit, et /feedback qui permet à l'utilisateur de signaler une prédiction incorrecte, alimentant ainsi le suivi en production.

Interface de test — Streamlit

Une interface locale développée avec Streamlit permet de tester l'API de manière interactive. L'utilisateur saisit un tweet en anglais, l'application appelle l'endpoint /predict de l'API déployée sur Azure et affiche le résultat (sentiment positif ou négatif avec son score). En cas de prédiction jugée incorrecte, l'utilisateur peut le signaler via un bouton de feedback, ce qui déclenche un appel à l'endpoint /feedback et envoie une trace vers Azure Application Insights pour alimenter le suivi en production.
